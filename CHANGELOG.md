## [Unreleased]

### Добавлено

- Имена и аватары Steam вместо «Игрок 166573769»: в шапке профиля (со ссылкой на профиль Steam), на вкладке «С кем играю», в составе матча (новая колонка «Игрок» со ссылкой на профиль). Сервер сам подтягивает профили всех встреченных игроков у deadlock-api в фоне: до 1000 за запрос, не чаще раза в минуту, обновление раз в 7 дней. Друзья из Steam отмечены среди союзников.
- RPC `ListProfiles` (`GET /v1/profiles?account_ids=…`): профили Steam пачкой; у `Peer` — флаг `steam_friend`.
- Поиск игрока по ссылке на профиль Steam (`steamcommunity.com/profiles/…` и `steamcommunity.com/id/…`), а также по SteamID2 (`STEAM_0:…`) и SteamID3 (`[U:1:…]`). Ссылку с ником разрешает новый RPC `ResolveSteamVanity` (`GET /v1/steam/vanity/{vanity}`) через публичную страницу профиля Steam; если Steam не отвечает, форма предлагает ссылку вида `/profiles/…`.
- Вкладка «С кем играю» в профиле: винрейт соло и с друзьями, по размеру пати; карточки друзей (винрейт вместе и в остальных матчах, частый герой, последний общий матч); герои, против которых проседаешь и с которыми выигрываешь; таблицы союзников и соперников со ссылками на профили.
- RPC `ListPlayerPeers` (`GET /v1/players/{account_id}/peers`): союзники, соперники, герои рядом и против, матчи по числу друзей в команде. Работает для любого игрока из сохранённых матчей.
- Вкладка «Прогресс» в профиле игрока (вкладки «Герои» и «Матчи» переехали на `/players/{id}/heroes` и `/players/{id}/matches`, старые ссылки перенаправляются): форма — последние 30 матчей против предыдущих 30; тренд по месяцам (души в минуту, KDA, смерти и винрейт); уровень лобби по месяцам; скорость развития — души к 5/10/15/20 минуте, время до 10k/20k/30k душ, источники душ, герои с самым быстрым стартом; винрейт по номеру матча в сессии, после серий поражений и по часам; рекорды и серии.
- RPC `ListPlayerMatchFacts` (`GET /v1/players/{account_id}/facts`): сводка каждого матча игрока для трендов.
- Уровень лобби (средний ранг команд) сохраняется для каждого матча. После обновления сервер при старте сам пересобирает уже загруженные матчи из сохранённых `.meta`, без повторной загрузки.
- Иконки героев, предметов и способностей в таблицах, заголовке разбора и итоговых предметах. Достаются из установленной игры: `go run ./tools/gamedata -icons data/icons`; без них показываются заглушки. Новая переменная фронта `ICONS_DIR`.
- Редизайн веб-интерфейса: тёмная монохромная тема, сортировка по любой колонке и фильтры во всех таблицах, длинные таблицы сворачиваются.
- Интерфейс на двух языках (русский, английский): по языку браузера, переключатель в шапке, страница настроек. Имена героев и предметов по умолчанию английские, русские — в настройках.
- Все ошибки в интерфейсе локализованы: недоступный или сбойный API показывает объяснение и кнопку «Повторить» вместо страницы 500; неверная ссылка — 404.
- `ListPlayerMatches`: сортировка (`sort`, `ascending`), фильтры (`result`, `game_mode`, `meta_status`) и общее число найденных матчей (`total`).
- Веб-интерфейс (`web/`, сервис `web` в `docker-compose.yml`, http://localhost:3000): поиск игрока по account id или SteamID64, профиль со статистикой и кнопкой синхронизации, история матчей с фильтром по герою и пагинацией, разбор игрока в матче (график душ всех игроков, таблица матча, итоговые предметы, источники душ, смерти, порядок покупок и улучшений способностей).
- Статистика по героям: RPC `ListPlayerHeroStats` (`GET /v1/players/{account_id}/heroes`) и таблица героев в профиле (матчи, винрейт, средние K/D/A, KDA, души в минуту, последний матч; клик по герою фильтрует историю).
- Dev-стек на мок-данных `docker-compose.dev.yml` (http://localhost:3001) и `npm run dev:mock` в `web/`: интерфейс работает без Postgres, Go-сервера и сети.
- Переменная `TZ` в `.env`: часовой пояс дат в веб-интерфейсе (по умолчанию UTC).
- gRPC API `deadlock.v1.StatsService` с REST-gateway: профиль игрока, история матчей, таблица матча, детальный разбор игрока в матче, статические данные игры.
- Хранение в Postgres: история матчей, сырой `.meta` и производные таблицы (срезы статистики, покупки предметов, смерти).
- Фоновая синхронизация: периодический опрос истории по `SYNC_ACCOUNTS`, очередь загрузки метаданных с повторами и экспоненциальной паузой.
- Названия героев и предметов (EN/RU), слот и тир предметов — из файлов игры, снимок встроен в бинарник.
- CLI `dlstat` для отладки: `history`, `match <id>`, `meta <file>`.
- `SYNC_ACCOUNTS` и `-account` принимают как 32-битный account id, так и SteamID64.
- API принимает SteamID64 везде, где ожидается `account_id` (например, `/v1/players/76561199477771562`); в ответах по-прежнему 32-битный account id.

### Исправлено

- Состояние синхронизации игрока больше не зависает в `running` после аварийной остановки сервера: при старте такие записи переводятся в `error` с пояснением `interrupted by restart`.
- `SyncPlayerResponse.queued_meta` показывает число ожидающих метаданных матчей этого игрока, а не размер всей очереди.

### Изменено

- Составы команд в разборе матча — друг под другом во всю ширину, чтобы колонки не обрезались.
- Формат `page_token` у `ListPlayerMatches` — `<значение сортировки>_<match_id>`; старые токены (только `match_id`) отклоняются с `InvalidArgument`. Токен по-прежнему непрозрачный: брать из `next_page_token`.
- Сервер завершается с ненулевым кодом, если упал gRPC- или HTTP-listener (раньше выходил с кодом 0, и перезапуск по `restart: unless-stopped` выглядел штатной остановкой).
- `SYNC_EVERY` и `META_INTERVAL` должны быть положительными: нулевое или отрицательное значение теперь ошибка конфигурации при старте, а не паника тикера.
- Некорректный id в `SYNC_ACCOUNTS` (ноль, значение между 2³² и диапазоном SteamID64) — ошибка при старте, раньше молча превращался в другой account id.

### Безопасность

- Текст внутренних ошибок (в том числе ошибок SQL) больше не возвращается клиентам API: в ответе `internal error`, подробности — в логе сервера.
- `/healthz` при недоступной БД отвечает `database unavailable` без текста ошибки подключения.
