# Грабли и известные проблемы

Живой документ. Два раздела: **грабли** — неочевидные факты, на которые уже наступали (читать, когда что-то ведёт себя странно), и **известные проблемы / долг** — что сознательно оставлено как есть.

Как вести:

- Потратил заметное время на неочевидную причину → запись в «Грабли»: симптом, причина, что делать.
- Оставил недоделку, обходной путь или нашёл баг, который не чинишь сейчас → запись в «Известные проблемы» с датой.
- Починил проблему → удалить запись (история остаётся в git и в changelog).
- Писать коротко и конкретно, со ссылкой на файл.

## Грабли

### Данные Valve

- **Файлы на CDN называются `*.meta.bz2`, но внутри zstd.** Расширению не верить; `internal/compress` определяет формат по magic-байтам. В кэше и тестовых данных файлы лежат с честным расширением `.zst`.
- **Реплеи исчезают.** Valve удаляет старые файлы, провайдер перестаёт отдавать соли. Это штатная ситуация (`meta_status = 'expired'`), а не ошибка; повторять бесполезно. По той же причине `matches.meta_raw` — единственная копия данных.
- **`item_id` — не порядковый номер, а хэш**: `MurmurHash2(lower(ключ), 0x31415926)` (`gamedata.HashKey`). Под одним полем приходят и предметы магазина, и способности героев.
- **`uint32` не влезает в `integer` Postgres.** `account_id` и `item_id` бывают больше 2³¹ → в схеме `bigint`, при чтении — через `int64` (`queries.go`).
- **Account id и SteamID64 — разные числа** одного аккаунта (разница — константа `76561197960265728`). Везде внутри — 32-битный account id; на входе принимаются оба (`source.ParseAccountID`).
- **Протобафы Valve не компилируются штатным `protoc`**: они выгружены из бинарников и содержат нестандартные опции (`boxed_type`, `additional_includes`, …). `tools/protogen` копирует нужные файлы во временный каталог и вычищает опции. Предупреждения `Import … is unused` при генерации — норма.
- **Мелкие `*.vdata_c` сжаты LZ4, который наш KV3-декодер не поддерживает** (`kv3: LZ4 compression not supported yet`). Крупные файлы, которые нам нужны (`heroes`, `abilities`), — zstd. Фикстуру для тестов выбирать из тех, что декодируются.
- **Генерируются не все файлы `proto/deadlock`**, а только замыкание импортов `gameRoots`. Нужен тип из другого файла — добавить файл в `gameRoots`.
- **После патча игры** могут появиться неизвестные герои/предметы (в API придут id без имён) и новые поля в метаданных. Порядок действий — development.md, «После патча игры».

### Инструменты и окружение

- **Версия `protoc` попадает в заголовки сгенерированных файлов.** Другая версия `protoc` на другой машине даст diff во всех `*.pb.go` без изменения сути. Плагины закреплены (`tools/dev`), сам `protoc` — нет.
- **На Windows нет `make`**, поэтому раннер — `go run ./tools/dev`. `go test -race` на Windows требует gcc; без него гонки проверяет только CI.
- **Интеграционный тест БД дописывает `&search_path=…` к `TEST_DATABASE_URL`** — в URL уже должен быть хотя бы один параметр (`?sslmode=disable`), иначе строка подключения сломается.
- **Тесты БД кэшируются Go** как любые другие: `go test ./internal/db` может показать `(cached)`, хотя база изменилась. `dev test-db` запускает с `-count=1`.
- **Порт 5432 занят локальным Postgres** → контейнер из compose не стартует. Остановить локальный или поменять проброс порта и `TEST_DATABASE_URL`.
- **pre-commit хук запускает полный `check`** (несколько секунд, первый раз дольше из-за сборки кэша линтера). Хук не установлен, пока не выполнен `dev setup`.

### Код

- **`context.Canceled` при остановке — не сбой загрузки.** `processMeta` не записывает неудачу, если отменён контекст, иначе каждое завершение процесса сжигало бы попытку у матча в работе.
- **`embed`-снимок `gamedata` общий на весь процесс**: `gamedata.Embedded()` возвращает один и тот же указатель, изменять данные нельзя.
- **Внутренние ошибки не доходят до клиента**: интерцептор заменяет текст `Internal` на `internal error`. Причину искать в логе сервера по `method` и `err`.
