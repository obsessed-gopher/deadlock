# Грабли и известные проблемы

Живой документ. Два раздела: **грабли** — неочевидные факты, на которые уже наступали (читать, когда что-то ведёт себя странно), и **известные проблемы / долг** — что сознательно оставлено как есть.

Как вести:

- Потратил заметное время на неочевидную причину → запись в «Грабли»: симптом, причина, что делать.
- Оставил недоделку, обходной путь или нашёл баг, который не чинишь сейчас → запись в «Известные проблемы» с датой.
- Починил проблему → удалить запись (история остаётся в git и в changelog).
- Писать коротко и конкретно, со ссылкой на файл.

## Грабли

### Данные Valve

- **Личного ранга в `.meta` нет.** `player_rank_data` пуст у всех игроков во всех матчах, в том числе рейтинговых. Есть только `average_badge_team0/1` — средний бейдж команды, и то не везде (в матчах с июля 2026 его тоже нет). Поэтому в профиле «уровень лобби», а не ранг; настоящий ранг/MMR — из deadlock-api (часть 4 roadmap).
- **Бейдж упакован как `уровень × 10 + подуровень`, подуровень 1..6.** Усреднять упакованные числа нельзя: (72 + 81) / 2 = 76 — «Archon 6», которого нет между Archon 2 и Oracle 1. Усреднять в линейной шкале (`(уровень − 1) × 6 + подуровень − 1`): `db.lobbyBadge`, `lib/progress.ts` (`badgeStep`/`stepBadge`).
- **Пати в `.meta` нет** (`party_id` отсутствует). «Друг» угадывается по составам: союзник с 5+ общими матчами (`db.FriendMinMatches`). На реальных данных соперники повторяются не больше 4 раз за 680 матчей, так что порог отделяет напарников от случайных людей; но случайный союзник, попавшийся 5 раз, тоже станет «другом». Точнее — `same_party` у deadlock-api (по списку друзей Steam), часть 2 roadmap.
- **Винрейт «с человеком» по 2–4 матчам — шум** (±40 п.п.). В интерфейсе цветом отмечается отклонение только от 10 общих матчей (`MIN_SAMPLE` в `lib/peers.ts`), выводы — от 20 (`MIN_BUCKET`).
- **Файлы на CDN называются `*.meta.bz2`, но внутри zstd.** Расширению не верить; `internal/compress` определяет формат по magic-байтам. В кэше и тестовых данных файлы лежат с честным расширением `.zst`.
- **Рейтинг — не отдельный `game_mode`**: у рейтинговых матчей `game_mode = 1` (обычный) и `match_mode = 4`. Фильтр по `game_mode` смешивал рейтинг с обычными; для людей — `MatchQueue` (`db.queueOf`, `lib/queue.ts`). Street Brawl — `game_mode = 4`; Hero Labs, боты, лобби — «другое».
- **Ключ deadlock-api ускоряет соли в 100 раз**: без ключа соли, которых нет в базе deadlock-api, берутся у Steam по 3 запроса в час на IP, с ключом (`DEADLOCK_API_KEY`, заголовок `X-API-Key`) — 300 в час. Ключ дают за поддержку на Patreon; в OpenAPI самого способа получения нет, вопрос — в Discord deadlock-api.
- **Соли, которых нет в базе deadlock-api, он берёт у Steam — 3 запроса в час на IP.** Раньше каждый 429 сжигал попытку, и за 5 попыток матч навсегда становился `failed` (392 матча из 1259). Теперь 429 — отсрочка по `Retry-After`, а соли нужны редко: сначала `.meta` берётся из хранилища deadlock-api.
- **deadlock-api отказывает в солях матчам, метадата которых у него уже есть** (400 «won't be fetched, as it has metadata already»; в OpenAPI этого нет). Такие матчи качаются через `/metadata/raw`. Миграция `0004` один раз вернула в очередь матчи, упавшие по этим двум причинам.
- **`/metadata/raw` отдаёт настоящий bzip2**, в отличие от одноимённых файлов CDN (там zstd). `meta_raw` может быть в любом из двух форматов.
- **Реплеи исчезают.** Valve удаляет старые файлы, провайдер перестаёт отдавать соли. Это штатная ситуация (`meta_status = 'expired'`), а не ошибка; повторять бесполезно. По той же причине `matches.meta_raw` — единственная копия данных.
- **`item_id` — не порядковый номер, а хэш**: `MurmurHash2(lower(ключ), 0x31415926)` (`gamedata.HashKey`). Под одним полем приходят и предметы магазина, и способности героев.
- **`uint32` не влезает в `integer` Postgres.** `account_id` и `item_id` бывают больше 2³¹ → в схеме `bigint`, при чтении — через `int64` (`queries.go`).
- **Account id и SteamID64 — разные числа** одного аккаунта (разница — константа `76561197960265728`). Везде внутри — 32-битный account id; на входе (API, `SYNC_ACCOUNTS`, CLI) принимаются оба (`source.NormalizeAccountID`). Поэтому `account_id` в запросах API — `uint64`, а в ответах — `uint32`.
- **`upgrade_id` в покупках означает разное.** У предметов магазина там всегда `1`. У способностей героя первая запись (`upgrade_id = 0`) — открытие способности, следующие — очки улучшения, и `upgrade_id` у них — хэш, которого нет среди ключей `abilities` в gamedata. Уровень улучшения определяется порядком записей этой способности (1, 2, 3), а не значением `upgrade_id`.
- **Протобафы Valve не компилируются штатным `protoc`**: они выгружены из бинарников и содержат нестандартные опции (`boxed_type`, `additional_includes`, …). `tools/protogen` копирует нужные файлы во временный каталог и вычищает опции. Предупреждения `Import … is unused` при генерации — норма.
- **Мелкие `*.vdata_c` сжаты LZ4, который наш KV3-декодер не поддерживает** (`kv3: LZ4 compression not supported yet`). Крупные файлы, которые нам нужны (`heroes`, `abilities`), — zstd. Фикстуру для тестов выбирать из тех, что декодируются.
- **Генерируются не все файлы `proto/deadlock`**, а только замыкание импортов `gameRoots`. Нужен тип из другого файла — добавить файл в `gameRoots`.
- **После патча игры** могут появиться неизвестные герои/предметы (в API придут id без имён) и новые поля в метаданных. Порядок действий — development.md, «После патча игры».

### Инструменты и окружение

- **openapi-typescript не читает OpenAPI v2**, а grpc-gateway генерирует только v2 (7.x понимает только OpenAPI 3, 6.x тоже отказывается от 2.0 и тянет уязвимый `undici`). Поэтому TS-типы делает свой `tools/protogen/tsgen.go`.
- **`next build` переписывает `web/tsconfig.json`** (добавляет `allowJs`, пути `.next/types`). Это штатно, изменения коммитить.
- **`node --test` (strip-types) не понимает parameter properties** (`constructor(readonly x: T)`) и `enum`: падает с `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`. Поля класса объявлять явно.
- **У Next.js свой скрытый `role="alert"`** (объявление маршрута). В e2e `getByRole("alert")` находит два элемента — фильтровать по тексту.
- **Даты в клиентских компонентах → ошибка гидрации**, если часовой пояс сервера и браузера разный. Даты и числа форматируются на сервере (`lib/views.ts`), в `DataTable` приходит текст.
- **`click().catch()` на несуществующей кнопке ждёт весь таймаут теста** (30 с), а не падает сразу. Условие проверять заранее.
- **`next start` не работает с `output: "standalone"`** (предупреждение и неполная раздача статики). Production-сборку запускать как в Docker: `node .next/standalone/server.js` после копирования `.next/static` (`web/scripts/standalone.ts`, это делает `npm run e2e`).
- **MCP-серверы через `npx` на нативном Windows** запускаются только через `cmd /c npx …` (`.mcp.json`), иначе процесс не стартует.
- **Порты стеков**: прод 3000/8080, dev-compose 3001/8090, `dev:mock` 3002/8092, e2e 3200/8091. Новый стек — новые порты, иначе `reuseExistingServer` Playwright молча подключится к чужому серверу.
- **MCP-сервер Playwright падает с `CONNECTION_CLOSED`**, если Claude Code запущен из процесса, который не видит Node (GoLand/терминал открыты до установки Node). В `.mcp.json` каталог Node явно добавлен в `PATH` сервера; после правки — `/mcp` → переподключить или перезапуск сессии.
- **Иконки предметов и способностей — белые глифы на прозрачном**: на белом фоне (превью, просмотрщик) кажутся пустыми. В интерфейсе они лежат на плитке цвета слота.
- **Скриншот Playwright MCP во время гидратации даёт ошибку `hydrated but some attributes … didn't match`** про `caret-color: transparent` на полях ввода: Playwright прячет курсор стилем. Это не баг страницы; проверять консоль после обычной загрузки без снимка.
- **`page.keyboard.type` в Playwright набирает символы вне US-раскладки (кириллицу) через `insertText`, без `keydown`.** Всё, что слушает клавиши (поиск по первым буквам в `Select`), такой ввод не видит; в e2e набирать латиницей.
- **Полностраничный скриншот сразу после загрузки показывает пустые иконки** ниже первого экрана: `loading="lazy"`. Прокрутить страницу перед снимком.
- **После установки Node.js уже открытые терминалы и GoLand не видят `node`/`npm`**: PATH обновляется только у новых процессов. Перезапустить терминал или IDE.
- **Версия `protoc` попадает в заголовки сгенерированных файлов.** Другая версия `protoc` на другой машине даст diff во всех `*.pb.go` без изменения сути. Плагины закреплены (`tools/dev`), сам `protoc` — нет.
- **Зелёный `check` на Windows не гарантирует зелёный CI на Linux.** Пример: `filepath.ToSlash` заменяет `` только на Windows, и поиск по пути в VPK работал локально, но падал в CI. Для нормализации путей *из данных* (а не путей ОС) использовать `strings.ReplaceAll`, для путей ОС — `filepath`. Проверка — `go run ./tools/dev test-linux`.
- **На Windows нет `make`**, поэтому раннер — `go run ./tools/dev`. `go test -race` на Windows требует gcc; гонки проверяются через `dev test-linux` и в CI.
- **Интеграционный тест БД дописывает `&search_path=…` к `TEST_DATABASE_URL`** — в URL уже должен быть хотя бы один параметр (`?sslmode=disable`), иначе строка подключения сломается.
- **Тесты БД кэшируются Go** как любые другие: `go test ./internal/db` может показать `(cached)`, хотя база изменилась. `dev test-db` запускает с `-count=1`.
- **Порт 5432 занят локальным Postgres** → контейнер из compose не стартует. Остановить локальный или поменять проброс порта и `TEST_DATABASE_URL`.
- **pre-commit хук запускает полный `check`** (несколько секунд, первый раз дольше из-за сборки кэша линтера). Хук не установлен, пока не выполнен `dev setup`.

### Steam GC

- **go-steam привязывает соединение к контексту `ConnectContext`.** Отмена контекста рвёт TCP-сессию. Поэтому `steamgc.Dial` подключается на контексте сессии (`context.WithoutCancel`), а переданный контекст лишь ограничивает ожидание приветствия GC. Симптом ошибки — `disconnected` через долю секунды после `logged on`.
- **GC ограничивает соли.** Около 50 запросов `GetMatchMetaData` подряд, потом `k_eResult_RateLimited` (окно пока не измерено). Бот отвечает на это паузой путей через соли на 10 минут (`steamgc.RetryBusy`). Очередь идёт от новых матчей к старым, поэтому лимит бьёт прежде всего по старому хвосту.
- **История из GC — одна страница (50 матчей).** Полную историю даёт deadlock-api; `MergedHistory` объединяет обе. У нового отслеживаемого аккаунта без deadlock-api видны только последние 50 матчей.
- **Чужую историю GC отдаёт только друзьям бота** (`k_eResult_InvalidPermission` иначе): для неотслеживаемых игроков работает только deadlock-api.

### Код

- **`context.Canceled` при остановке — не сбой загрузки.** `processMeta` не записывает неудачу, если отменён контекст, иначе каждое завершение процесса сжигало бы попытку у матча в работе.
- **`embed`-снимок `gamedata` общий на весь процесс**: `gamedata.Embedded()` возвращает один и тот же указатель, изменять данные нельзя.
- **Внутренние ошибки не доходят до клиента**: интерцептор заменяет текст `Internal` на `internal error`. Причину искать в логе сервера по `method` и `err`.
