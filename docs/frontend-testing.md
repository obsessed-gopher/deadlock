# Тестирование фронтенда

Обязательно для любого изменения в `web/`. Три уровня, и каждый ловит своё: юнит — логику, e2e — сценарии и регрессии, Playwright MCP — то, что видно только глазами (вёрстка, наложения, читаемость, мобильный вид).

## Мок-данные

Иконок в e2e нет (`ICONS_DIR=e2e/no-icons`): тесты проверяют, что вместо них приходят заглушки, а не 404. Для сверки глазами dev-стек монтирует `./data/icons` — выгрузить их заранее (`go run ./tools/gamedata -icons data/icons`).

Фронт разрабатывается и тестируется на мок-API, а не на настоящем сервере:

- `web/mock/fixtures/` — снимок настоящего API: gamedata, 120 строк истории аккаунта 1517505834 и полные разборы (все игроки) трёх матчей, включая Street Brawl на 8 игроков. Коммитится в git.
- `web/mock/api.ts` — те же маршруты, JSON и формат ошибок, что у Go-gateway: пагинация, фильтр по герою, SteamID64, 404/400, статистика по героям считается из строк истории. Покрыт `mock/api.test.ts`, в том числе инвариантом «каждая строка с `META_STATUS_OK` ведёт на разбор, который мок умеет отдать».
- `web/mock/server.ts` — HTTP-обёртка (порт `MOCK_PORT`).
- `web/mock/capture.ts` — пересъёмка фикстур с работающего сервера: `node mock/capture.ts http://localhost:8080 1517505834`. Только руками: ходит в настоящий API.

**Изменился API** (новый RPC, поле, маршрут) → в том же изменении: `dev gen`, поддержка в `mock/api.ts` + тест в `mock/api.test.ts`, при необходимости пересъёмка фикстур. Иначе e2e и dev-стек отстанут от прода.

## Уровни

### 1. Юнит-тесты (`npm test`, входит в `dev web`)

- Вся логика без React — в `src/lib` (форматирование, расчёты, разбор данных). Каждая функция — тест рядом (`*.test.ts`), `node:test` + `node:assert/strict`, без зависимостей.
- Граничные случаи обязательны: ноль, пустой список, деление на ноль, неизвестный id из gamedata.
- Данные Valve с подвохом (как `upgrade_id`) — тест на реальной форме данных из фикстур с комментарием, откуда она.

### 2. E2E (`go run ./tools/dev e2e`)

Playwright, `web/e2e/`. Собирается production-сборка (`next build` → standalone-сервер, как в Docker-образе) и запускается против мок-API. Два проекта: `desktop` (Desktop Chrome) и `mobile` (Pixel 7). Часовой пояс зафиксирован (`TZ=UTC`).

Что покрывать:

- каждый пользовательский сценарий новой страницы или фичи: переходы, фильтры, пагинация, формы, server actions;
- состояния: пусто, не найдено (404), неизвестный игрок;
- исправленный баг UI — e2e-тест, который без исправления падает.

Правила:

- Локаторы — по роли и доступному имени (`getByRole("table", { name: "Матчи" })`, `getByRole("button", { name: … })`), а не по CSS-классам. Нужна точка привязки — сначала `aria-label`, это заодно улучшает доступность.
- Ожидаемые значения не хардкодить, а брать из фикстур через `e2e/helpers.ts` (`fx`, `rows`, `heroes`, `look`): после пересъёмки фикстур тесты не ломаются.
- Ошибка в консоли браузера или неперехваченное исключение роняет тест автоматически (фикстура `consoleErrors` в `helpers.ts`). Ожидаемую ошибку (например, ответ 404 на документ) отфильтровать в самом тесте явно и узко.
- Каждая страница проверяется на отсутствие горизонтальной прокрутки (`expectNoHorizontalScroll`): широкие таблицы прокручиваются внутри `.table-wrap`.
- Никаких `waitForTimeout`: только веб-первые ассерты `expect(...).toBeVisible()/toHaveURL()`.
- Скриншот-тесты (`toHaveScreenshot`) не используем: шрифты Windows и Linux различаются, эталоны будут ложно падать. Визуальная проверка — через Playwright MCP.
- Без сети: всё — через мок.

При падении в CI отчёт и трейсы прикладываются артефактом `playwright-report`; локально — `npx playwright show-trace test-results/<тест>/trace.zip`.

Обязательные сценарии для фронта (держать в актуальном состоянии вместе с кодом):

- **каждая таблица**: сортировка по колонке в обе стороны (проверять порядок значений, а не только `aria-sort`), поиск, каждый фильтр, «Показать все» / «Свернуть»;
- **обе локали**: страница в `en` (`test.use({ locale: "en-US" })`) и в `ru`; переключатель в шапке; настройки; имена героев английские по умолчанию и русские после выбора в настройках (`e2e/i18n.spec.ts`);
- **ошибки**: внутренняя ошибка API и недоступность — локализованная страница с HTTP 200, неверный id и неизвестный матч — 404, мусор в URL — страница по умолчанию, неудачная синхронизация — сообщение на месте (`e2e/errors.spec.ts`).

Мок падает нарочно на «аварийных» id: матч `500` → Internal, игрок `503` → Unavailable, синхронизация игрока `504` → Unavailable (`mock/api.ts`). Не использовать эти id как обычные данные.

Ожидаемые тексты брать из словарей (`ru.t(…)`, `en.t(…)` из `e2e/helpers.ts`), а не писать литералом: тогда правка формулировки не ломает тесты, а пропавший ключ — ломает.

### 3. Сверка через Playwright MCP

E2E проверяют сценарии, но не то, как страница выглядит. Поэтому каждое видимое изменение UI перед завершением задачи сверяется глазами через MCP-сервер Playwright (`.mcp.json` в корне; при первом запуске Claude Code спросит разрешение на сервер).

Порядок:

1. Поднять dev-стек на моке: `docker compose -f docker-compose.dev.yml up -d --build --wait` (http://localhost:3001) или `cd web && npm run dev:mock` (http://localhost:3002, с hot reload).
2. Через MCP открыть каждую затронутую страницу; сделать снимок экрана при 1280×800 и при ширине телефона (`browser_resize` 390×844). Иконки грузятся лениво: перед полностраничным снимком прокрутить страницу, иначе ниже первого экрана будут пустые места.
3. Проверить: ничего не наезжает и не обрезано, таблицы читаются, числа выровнены, цвета команд и слотов различимы, контраст текста не ниже 4.5:1; страница в **обеих локалях** (русские строки длиннее — переносы, обрезка) и с русскими именами в настройках.
4. Прочитать консоль (`browser_console_messages`): ошибок и предупреждений гидрации быть не должно.
5. Пройти новый сценарий руками (клики, фильтры, кнопки) и посмотреть, что меняется именно то, что ожидалось.
6. Найденное — исправить; если это регрессия, которую можно поймать автоматически, — добавить e2e-тест.

В отчёте о задаче написать, какие страницы сверены и что найдено. Если MCP недоступен (сервер не подключён) — так и сказать, а не считать проверку пройденной; запасной вариант — скриншоты `page.screenshot()` из временного Playwright-теста.

## Чек-лист изменения фронта

- [ ] Логика в `src/lib` + юнит-тесты.
- [ ] Новые строки — ключи в `en.ts` и `ru.ts`, ни одного литерала в разметке.
- [ ] Новая таблица — через `DataTable`: сортировка, фильтр/поиск, сворачивание; e2e на всё это.
- [ ] Новый запрос к API — через `attempt` и `ErrorState`, без 500.
- [ ] E2E на новый сценарий (desktop и mobile проходят).
- [ ] API изменился → мок и его тесты обновлены.
- [ ] `go run ./tools/dev web` и `go run ./tools/dev e2e` зелёные.
- [ ] Сверка через Playwright MCP на dev-стеке: desktop, mobile, консоль.
