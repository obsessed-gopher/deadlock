# Правила написания кода

Go — разделы ниже; TypeScript (фронт) — в конце, раздел «Фронтенд (TypeScript)». Тесты фронта — [frontend-testing.md](frontend-testing.md).

База — [Effective Go](https://go.dev/doc/effective_go) и [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments). Ниже — то, что специфично для проекта или чаще всего нарушается. Форматирование и большую часть механических правил проверяет `dev check`; здесь то, что линтер не поймает.

## Общее

- Простота важнее гибкости. Не вводить абстракцию, слой или параметр «на будущее»; интерфейс появляется, когда есть второй потребитель или нужен фейк в тесте.
- Новая зависимость — крайняя мера (см. architecture.md, «Минимум зависимостей»). Сначала stdlib.
- Комментарии объясняют **почему** и неочевидные факты о данных Valve (`// Files on replay*.valve.net are named *.bz2 but are currently zstd`), а не пересказывают код. У каждого пакета — комментарий пакета, у каждого экспортируемого идентификатора — doc-комментарий, начинающийся с его имени.
- Язык кода, комментариев, логов и ошибок — английский.
- Экспортировать только то, что нужно другим пакетам. Поля структур, которые использует только сам пакет, — неэкспортируемые.

## Ошибки

- Оборачивать с контекстом через `%w`: `fmt.Errorf("meta: decompress %s: %w", path, err)`. Текст — со строчной буквы, без точки, без слов «failed to»/«error».
- Сравнивать через `errors.Is` / `errors.As`, никогда `==` (ошибки приходят обёрнутыми).
- Сентинелы — `var ErrNotFound = errors.New(...)` на уровне пакета, с именем `ErrXxx`/`errXxx`. У каждого слоя свой: `source.ErrNotFound`, `db.ErrNotFound`; перевод одного в другое — на границе слоёв (`pgx.ErrNoRows` → `db.ErrNotFound` → `codes.NotFound`).
- Ошибку либо обрабатывают, либо возвращают — не то и другое (не логировать и возвращать одновременно). Логирует верхний уровень: интерцептор gRPC, цикл воркера, `main`.
- Осознанно игнорируемая ошибка — явно: `_ = resp.Body.Close()`, при неочевидности с комментарием.
- `panic` — только для невозможных состояний при инициализации. В обработчиках запросов паники ловит интерцептор, но это страховка, а не механизм.
- Различать постоянные и временные сбои: от этого зависит, будет ли повтор (`errExpired` в `syncer`). Новая причина сбоя загрузки — решить, к какому классу она относится, и покрыть тестом.

## Контекст и конкурентность

- `context.Context` — первый параметр любой функции, которая ходит в сеть или БД; не хранить в структурах. HTTP-запросы — только `http.NewRequestWithContext`.
- Каждая горутина должна иметь понятный способ завершиться (обычно `ctx.Done()`). Циклы воркеров — `select` с `ctx.Done()` на каждом ожидании, никаких голых `time.Sleep`.
- Для завершающих действий после отмены (записать статус, освободить блокировку) — `context.WithoutCancel(ctx)`.
- У каждого `http.Client` задан `Timeout`; тело ответа всегда закрывается; чтение чужих ответов ограничивается `io.LimitReader`.

## База данных

- Весь SQL — в `internal/db`, сырыми строками в обратных кавычках, ключевые слова заглавными.
- Только параметры `$1, $2…`. Конкатенация допустима лишь для идентификаторов из констант в коде (имена таблиц), никогда — для значений.
- Несколько связанных записей — в одной транзакции через `pgx.BeginFunc`. Массовая вставка — `CopyFrom`.
- Запись должна быть идемпотентной (`ON CONFLICT`, удалить-и-вставить в транзакции): синхронизация повторяется.
- `rows.Close()` и проверка `rows.Err()` обязательны; где можно — `pgx.CollectRows`.
- `pgx.ErrNoRows` наружу не выпускать — превращать в `db.ErrNotFound`.
- `uint32` из игры, который может превысить 2³¹ (`account_id`, `item_id`), — `bigint` в схеме.

## Логирование

- Только `log/slog`, логгер передаётся явно (нет глобального). В проде — JSON в stdout.
- Сообщение — короткая константа в нижнем регистре; всё переменное — в атрибутах: `log.Info("meta stored", "match", id, "players", n)`. Не `fmt.Sprintf` в сообщении.
- Ключи атрибутов — `snake_case`, устоявшиеся: `err`, `match`, `account`, `method`, `dur_ms`.
- Уровни: `Error` — нужна реакция человека; `Warn` — сбой, который система переживёт сама (повтор); `Info` — события жизненного цикла и итоги операций.
- Не логировать секреты и `DATABASE_URL`.

## API и protobuf

- Поля — `snake_case`, единицы измерения в имени (`duration_s`, `abandon_time_s`), время — unix-секунды.
- Номера полей не менять и не переиспользовать.
- Обработчик RPC: проверить обязательные поля → вызвать `Store` → `toStatus(err)`. Бизнес-логики и SQL в обработчиках нет.
- Каждому RPC — комментарий в `.proto`: он попадает в OpenAPI.

## Тесты

- Тест лежит рядом с кодом, в том же пакете (`package syncer`), чтобы проверять и неэкспортируемое.
- Имена: `TestЧто_Условие` или просто `TestЧто`; несколько случаев — табличный тест с `t.Run(c.name, …)`.
- Только stdlib `testing`, без testify. Сообщение об ошибке содержит полученное и ожидаемое: `t.Errorf("limit = %d, want %d", got, want)`.
- `t.Fatal` — когда продолжать бессмысленно; иначе `t.Errorf`, чтобы увидеть все расхождения сразу.
- Фейки — небольшие структуры в `_test.go`, реализующие интерфейс потребителя. Встроенный nil-интерфейс (`Store`) даёт панику на неожиданном вызове — это желаемое поведение.
- Никакой сети: HTTP подменяется через `http.Client{Transport: …}`. Никаких `time.Sleep`: зависимость от времени — через параметры (`Interval`) или каналы.
- Тесты независимы и проходят в любом порядке (`-shuffle=on`): без общего изменяемого состояния между тестами.
- Тест, которому нужно внешнее (Postgres, установленная игра), начинается с `t.Skip`, если этого нет, и говорит в сообщении, что нужно задать.
- Проверять поведение, а не реализацию: что записано в хранилище и что вернулось, а не сколько раз вызван метод.

## Фронтенд (TypeScript)

- `strict` и `noUncheckedIndexedAccess` включены; `any` и `as` для обхода типов не использовать. Типы API — только из `src/api/schema.gen.ts` (генерируется, руками не править).
- Страницы — серверные компоненты; `"use client"` — только там, где нужна интерактивность (форма с состоянием). Данные — через `src/api/client.ts`, не `fetch` по месту.
- Изменение данных — server action (`actions.ts` рядом со страницей), формы работают и без JS.
- Логика без React — в `src/lib`, чистыми функциями с тестами. Компонент только раскладывает готовые значения.
- 64-битные числа API (`matchId`, `startTime`) — строки; сравнивать через `BigInt`, не `Number`.
- Код, комментарии, имена — английский; текст интерфейса — только из словарей (ниже).
- Доступность: у таблиц и полей — доступное имя (`aria-label` или `<label>`): на нём держатся и e2e-локаторы.
- Стили — `src/app/globals.css`, цвета только через токены в `:root`. Дизайн тёмный монохромный (макет — артефакт «Deadlock analytics redesign»): цвет несёт только смысл — итог, команда, слот предмета. Новых библиотек стилей и компонентов не добавлять без согласия владельца.
- Выпадающие списки — только `components/Select.tsx`, не браузерный `<select>` (его открытый список рисует ОС и он выбивается из темы). У `Select` — `label` и, если на странице несколько таблиц, `ariaLabel` «Таблица: Фильтр»; в GET-форме — `name`. Список работает с клавиатуры (стрелки, Home/End, Enter, Esc, первые буквы). Менять значение без JS нельзя — это осознанная плата за вид; отправка формы работает.
- Режим матча для людей — очередь (`lib/queue.ts`: обычный, рейтинг, Street Brawl, другое), а не `gameMode`: рейтинг — это `matchMode` обычного режима.
- Импорты внутри `web/` — с расширением `.ts`/`.tsx`, чтобы `node --test` и `node mock/server.ts` работали без сборки.

### Локализация (ru / en)

- Две локали интерфейса: `en` (эталонный набор ключей, `src/i18n/en.ts`) и `ru` (`src/i18n/ru.ts`, тип `Messages` требует каждый ключ). Ни одной строки интерфейса литералом в JSX или коде: только `t("ключ", { параметры })`. Новый текст — ключ в **оба** словаря; тест `i18n.test.ts` проверяет полноту и одинаковые `{плейсхолдеры}`.
- Язык интерфейса: cookie `lang` → `Accept-Language` → английский (`resolvePrefs`). Переключатель — в шапке и в настройках.
- **Имена героев и предметов** — отдельная настройка (cookie `names`), по умолчанию **английские при любом языке интерфейса**. Имя выводить только через `i18n.name(x)` / `look.heroName(id)`, никогда `hero.name` или `hero.nameRu` напрямую.
- Числа, даты, проценты — через `i18n.num/date/pct/dec` (формат зависит от локали). **Форматировать на сервере**, в клиентские компоненты передавать готовый текст: часовой пояс сервера и браузера может различаться, иначе — ошибка гидрации.
- Значения enum из данных игры (команда, режим, тип матча, роль) — через `i18n.team/gameMode/matchMode/role`: у каждого запасной текст для значений, которые игра добавит позже.
- `<html lang>` = локаль; у переключателей языка — `lang` на элементе.

### Ошибки

- Пользователь видит только локализованные тексты по виду ошибки: `notFound`, `badRequest`, `unavailable`, `internal` (`src/lib/errors.ts`, ключи `error.<вид>.title/.text`). Текст ошибки API или сети на страницу не выводится никогда.
- **Без 500**: запросы страницы — через `attempt(() => api.…)`, неудача → `<ErrorState kind=… retryHref=…>` (HTTP 200, кнопка «Повторить»). `NotFound` от API и неверный id в URL → `notFound()` (HTTP 404, локализованная страница). `error.tsx` и `global-error.tsx` — последняя страховка, а не механизм.
- Server actions не бросают: возвращают `{ ok, message }` с локализованным текстом.
- Параметры URL (сортировка, фильтры, страница) — разбирать терпимо: мусор → значение по умолчанию (`parseMatchState`), а не 400.
- У клиента API таймаут (`AbortSignal.timeout`): зависший API → `unavailable`, а не висящая страница.

### Иконки

- Только через `components/Icon.tsx` и URL из `look.heroIcon/abilityIcon` (`lib/icons.ts`), не `<img>` по месту. Иконка декоративна (`alt=""`): имя всегда рядом текстом.
- Портреты героев — круглые; глифы предметов и способностей (белые на прозрачном) — на плитке цвета слота (`tileOf`).
- Не рассчитывать, что иконка есть: в CI и e2e вместо неё заглушка.

### Таблицы

- **У каждой таблицы — сортировка по каждой колонке и фильтр.** Клиентские таблицы — только через `components/DataTable.tsx` со спецификацией из `src/lib/views.ts` (`TableSpec`): клик по заголовку сортирует, повторный — меняет направление (`aria-sort`), есть поиск и/или селект-фильтры по смыслу данных.
- **Длинные таблицы сворачиваются** (`collapseAfter`: 10–12 строк) с кнопкой «Показать все N» — особенно там, где на странице несколько таблиц.
- Большие или постраничные данные (история матчей) сортируются и фильтруются **на сервере**: состояние в URL (`src/lib/matchQuery.ts`), заголовки — ссылки, фильтры — GET-форма; работает без JS. Сортировка на клиенте по одной странице выдачи — ошибка.
- Если данных мало и сравнивать нечего (5 источников душ) — не таблица, а другой вид (полосы, плашки).
- У таблицы — `label` (доступное имя): на нём держатся e2e-тесты. Несколько таблиц в одном разделе — видимая подпись `caption`.
